# Gates

Regenerated by `python scripts/gates.py` on 2026-10-30 at commit `68fa77b`. Every number in this file is measured by that command. Nothing else in the repository may state a figure this file does not contain.

A gate is a comparison against a named baseline. No agent is connected to the critic before it beats its baseline, and an agent that has not passed its gate abstains at runtime and keeps its gate report.

The majority class row is the one to read first. No figure in this table is a performance claim. The defensible statement is that the pipeline, the features and the attribution layer are in place, that the model orders genes better than any single descriptor measured here, and that it orders synonymous variants of one gene backwards on one of the two measured series.

**This clause of Gate A fails outright.** The served model's expected tier is negatively correlated with measured yield on the polymerase series, so it orders those variants backwards. The clause exists because a model that ranks a synonymous series backwards will drive a redesign search in the wrong direction, which is what Agent C is for.

## Gate C. Codon variant ranking

On Welch 2009, per series, Agent C must produce a positive Spearman rho on both the polymerase and the scFv series and must beat GC3 alone on both. Welch is held out entirely and is never trained on. Beating GC per cent alone overall is a harder bar and is reported but not required, because the per series comparison is the use case.

**Status: not passed.** Gate C failed. polymerase: rho +0.156 does not beat GC3 alone at +0.643; scFv: rho +0.212 does not beat GC3 alone at +0.394.

The per series figures recorded in the plan and in `src/agents/variant.py` are +0.643 on polymerase and +0.394 on scFv for GC3 alone. This run measures +0.643 and +0.394. Any divergence between the two is a change in the feature code and should be explained before it is accepted.

The artifact under test is `models/agent_c_variant_ranker.joblib`, a XGBRanker over 7 features a synonymous substitution can move, fitted on 74,900 sequences in 4,126 query groups.

Its training sequences are all 96 nt long. The Welch ORFs are 843 and 1,725 nt, so every figure in the table above is an extrapolation in sequence length, and the agent says so in its own domain check at runtime.

The secondary part of Gate C, on 825 held out query groups from the training source: mean Kendall tau within group +0.118 for the model against -0.076 for GC3 alone, so inside its own domain the model beats the baseline.

What this run did establish, and it is not nothing: unlike the tier model, the ranker is positive on both Welch series, so it no longer orders a synonymous series backwards. What it did not do is beat GC3, which is the bar, so the agent abstains and the redesign loop keeps ranking on the tier model with the GC3 corroboration check as its guard.

The overall figure, -0.289, is negative while both series are positive, which is not a contradiction. The two series are different proteins measured on different scales, so pooling them compares a polymerase variant against an scFv variant, which is a between gene comparison this agent has no opinion about. The per series figures are the ones the gate is defined on.

Nothing here was tuned against Welch and nothing may be. Welch is the held out external test set, so choosing between models by their Welch score would turn the gate into a training signal and there would be no external evidence left in the project.

The length mismatch is measured rather than assumed. Scoring the same model on only the first 96 nt of each Welch ORF, which is the window it was trained on, gives polymerase -0.268 against +0.156, scFv +0.217 against +0.212. The mean per series change is -0.210. Matching the window does not help, so the gap to GC3 is not merely an extrapolation in length: what the model learned on a 32 codon reporter fragment does not carry to whole genes. Training data from whole constructs is the thing to try next, not a different objective or more trees. This is a diagnostic and not the gate.

What is at stake, measured on the Boel table: Gz48v, which folds leader plus insert, tracks the expression score at rho 0.177, while `head_folding_48`, the servable insert only counterpart, reaches 0.141. The first is the feature the project cannot currently serve.

## Leakage

The one mistake that would invalidate everything: the critic is trained on the specialists' predictions, so if a specialist's training rows overlap the critic's training or evaluation rows, the critic learns that the specialist is more accurate than it is, and the agreement score becomes meaningless in exactly the cases it exists for. The guard is to cluster the union of every dataset once, assign every row a cluster id and a source label, reserve the critic pool by cluster, and never split by row anywhere.

No critic has been trained and none can be until the clustering above is unblocked. `tests/test_leakage.py` asserts that no critic model is loaded while the critic pool is unreserved, so this cannot be done by accident later.
